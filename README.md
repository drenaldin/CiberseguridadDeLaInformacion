## Cómo se evalúa la materia

La evaluación es **formativa y por competencias**: interesa el proceso y el desempeño, no la memorización. Cada instancia tiene una devolución escrita.

| Instancia | Cuándo | Qué se entrega |
|---|---|---|
| Diagnóstico inicial | Clase 1 | Cuestionario. **No lleva nota.** |
| Primera evaluación formativa | Clase 6 | Informe de análisis de superficie de ataque |
| Segunda evaluación formativa | Clase 12 | Informe de incidente del simulacro |
| Proyecto final | Clases 13–14 | Campaña de concientización + coevaluación |
| Autoevaluación | Clase 14 | Reflexión individual sobre el propio proceso |

Las competencias específicas del programa que se desarrollan son **CET1** (interpretar los fundamentos de la seguridad informática y las principales amenazas) y **CET2** (valorar y utilizar medidas y herramientas de protección).

## Antes de empezar: leé esto

> [!IMPORTANT]
> Este curso enseña conocimiento de **doble uso**: lo mismo que sirve para proteger un sistema sirve para atacarlo. Por eso hay reglas, y no son negociables.
>
> Leé el [**Acuerdo de uso responsable**](CODE_OF_CONDUCT.md) antes de la primera práctica. Lo vamos a firmar en clase.

> [!WARNING]
> En Uruguay, acceder a un sistema informático ajeno sin autorización es delito **aunque no rompas ni robes nada** (Ley N.º 20.327, art. 297 BIS del Código Penal). No existe la excusa de «entré para aprender». Todas las prácticas de este curso se hacen sobre entornos preparados para eso y con autorización escrita.
